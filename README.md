# DEEPest

**DEEPest** — офлайн, полностью текстовый, системный симулятор выживания с максимально глубокой, но вычислительно управляемой моделью организма, окружающей среды, предметов, общества и последствий действий.

Статус: **первый игровой прототип 0.1.0 / ТЗ v1.0**. Играбельный сценарий «Первая ночь» на Godot 4.6.3; целевая глубина ТЗ реализована частично. [Что работает и что остаётся](docs/PROTOTYPE_STATUS.md).

## Запуск

Откройте `project.godot` в **Godot 4.6.3** и нажмите F5 (основная сцена `scenes/main.tscn`), либо выполните:

```sh
godot --headless --editor --path . --import --quit
godot --path .
```

Интернет, аккаунт и сервер игре не нужны. Время идёт только во время действий. Все команды доступны кнопками, включая отмену долгой работы. На телефоне навигация находится в выпадающем списке сверху. Размер текста 100–200%, ручное сохранение, загрузка и новое прохождение — в «Настройках». Автосохранение ведётся отдельно от ручного и продолжается при следующем запуске.

Задача первой ночи: обжить дом, подготовить воду, помочь Нине, починить радио и встретить 06:00. Рекомендуемое зерно первого прохождения — **1998**. [Проверенный маршрут со спойлерами](docs/walkthrough.md).

Системы влияют друг на друга: утепление уменьшает приток воздуха; печь расходует кислород и дрова; нагрев воды отбирает тепло у комнаты; сырая одежда холодит тело; вода и пища усваиваются постепенно; NPC расходуют реальные запасы. Устройство мира и наблюдения персонажа разделены. Скрытые числа видны только в явной диагностике разработчика.

## Проверка

```sh
python3 tools/run_tests.py
```

Нужен Godot 4.6.3 в PATH (`godot`/`godot4`) либо `GODOT_BIN`. Runner создаёт временные writable XDG-каталоги, проверяет архитектурные границы, импорт проекта, все `tests/test_*.gd` и считает ошибки Godot провалом даже при exit 0. GitHub Actions запускает ту же команду; факт удалённого CI проверяется отдельно от локальных тестов.

Сборка пакета игры (без установки export templates):

```sh
mkdir -p builds
godot --headless --path . --export-pack Linux builds/DEEPest.pck
godot --main-pack builds/DEEPest.pck
```

APK и работа на физическом Android-устройстве пока не проверены. Godot Control-интерфейс проверен на desktop, портретном окне и при 200% текста.

## Основные принципы
- Это игра-песочница, а не книга с вариантами ответов: события возникают из состояния симуляции.
- Нет универсальной полоски HP, магических бонусов и произвольных шансов вместо причинно-следственных моделей.
- Игрок видит доступные ему ощущения, наблюдения, измерения и выводы — не внутренние числа организма.
- Реальные единицы измерения, сохранение вещества, тепла и энергии в пределах явно описанных приближений.
- Каждая подсистема заменяемая: определённые контракты, собственные данные, тесты, миграции, отсутствие жёстких связей с UI.
- Развитие проекта не должно ломать воспроизводимость, сохранения и соседние модули без явных миграций и тестов.
- Приоритет: Android 10 и слабое железо, сенсорный интерфейс; также ПК. Игра целиком офлайн.
- Сеттинг по умолчанию: постсоветская провинция, 1998 год, реалистичная альтернативная катастрофа; данные сеттинга заменяемые.

## Как работать по ТЗ
- Сначала изучить 00 и 01, затем соответствующую предметную спецификацию, 06 и 08.
- На каждую новую механику: модель состояния → формулы и источники/допущения → API → последствия → UI → сохранение → тесты → измерение скорости.
- Изменять систему через её публичный контракт, не обходя SimulationKernel и не прописывая скрытые исключения.
- Если требования конфликтуют, приоритет: корректность причинности и данных → воспроизводимость → производительность → наблюдаемость → удобство → визуальное оформление.
- Любое отступление фиксировать как ADR в docs/adr/ с причиной, альтернативами, последствиями и тестом.

**Важно:** главы 00–09 описывают целевой продукт. Наличие текста в ТЗ не означает, что функция реализована. Текущий объём и ограничения перечислены в матрице прототипа.
