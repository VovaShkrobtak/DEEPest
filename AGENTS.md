# DEEPest — обязательные инструкции для AI-агентов и разработчиков

Этот файл находится в корне для автоматических coding agents. Он описывает постоянные проектные ограничения. Перед любой реализацией, рефакторингом или ревью **прочитать README.md, docs/00_VISION.md, docs/01_ARCHITECTURE.md, docs/06_ENGINEERING_QA.md, docs/08_ACCEPTANCE.md, тематические документы 02–05 и обязательные главы 10–16**.

## Миссия
Строить полностью текстовый, системный, модульный, причинно-следственный офлайн-симулятор выживания DEEPest. Не подменять физику скриптовым событием, наблюдение скрытым знанием, а частично работающий код — обещанием реализации. Сеттинг — постсоветская провинция 1998 года: бесконечная зомби-песочница без обязательных заданий и победы; Godot 4.6.3 / typed GDScript, UI-independent ядро и Android 10. На Android горизонтальная ориентация по умолчанию, вертикальная — опция настроек.

## Непереговорные правила
1. WorldState — один источник истины; UI не мутирует его напрямую.
2. Все изменения через типизированные команды/транзакции/события SimulationKernel.
3. Каждая подсистема владеет своим состоянием; соседние подсистемы общаются через публичные контракты и учтённые потоки, без циклов.
4. Симуляция детерминирована для seed + версии + контента + action log; RNG потоки явные.
5. Использовать физические единицы, явно указывать допущения и ограниченные диапазоны достоверности; не придумывать научные факты.
6. Игрок получает только возможные наблюдения и знания. Debug view отделён от игрового.
7. Никакого универсального HP, магического крафта, бесконечных ресурсов, произвольных bonus multipliers и мгновенного восстановления.
8. Время, масса, энергия, объёмы, инвентарь, длительные действия и частичные результаты сохраняются консистентно.
9. Обязательно offline-by-default и полноценное сенсорное управление без мыши/ПК.
10. Приоритет модульности/тестов/мобильной производительности выше «красивого» демо, скрывающего неработающие процессы.
11. Не изменять ТЗ молча ради упрощения реализации: фиксировать ADR и согласованные последствия.
12. Отчёт о выполнении должен разделять implemented, tested, experimentally calibrated и still specified; не заявлять о пройденном CI без фактического запуска.

## Рабочий протокол
- До изменения: обследуй актуальный репозиторий, перечисли затрагиваемые модули, события и инварианты.
- Формулируй вертикальный срез (ввод → действие → симуляция → наблюдение → сохранение → тест), а не голый класс.
- Пиши схемы данных и public APIs раньше UI.
- При введении численного расчёта добавляй reference fixture/источник либо честный статус assumption.
- При изменении формата save добавляй migration и save/load regression.
- При багфиксе сначала воспроизвести в тесте; затем исправить причину, а не ловить симптом.
- Для новой механики создавать unit/property/integration/scenario тесты, включая крайние условия и time acceleration.
- Профилировать Android-критичные пути и журнал; никакой full world per-frame симуляции.
- Запускать доступные тесты и CI; в отчёте перечислять команды, результат, коммит и известные ограничения.

## Формат отчёта о PR
Цель и изменённые модули; новые/изменённые контракты; физические допущения; сохранения/миграции; тесты с фактическими результатами; показатели производительности; сквозные сценарии; известные ограничения; SHA и ссылка на PR/commit.

ТЗ описывает целевой продукт. **Уже есть первый игровой прототип, но глубокая симуляция далеко не полностью реализована.** По прямому указанию владельца все коммиты делать в `main` без веток и PR, пока не будет нового распоряжения.

## Дополнительные обязанности для zombie sandbox

- Не писать обязательный авторский сюжет, победу, спасательную миссию, «новую волну на день N» или respawn лута. Мир продолжается без окончания.
- Заражённые — персистентные сущности с физическим телом, реальным источником/путём миграции, ограниченной сенсорикой и возможностью потерять след. Место игрока нельзя передавать AI как всезнание; текущая coarse model — известное временное упрощение.
- Контакт вызывает физические травмы через Physiology и независимый ExposureRecord для будущего вымышленного патогена. Никакого универсального HP, гарантированного заражения по нажатию или магической починки дверей.
- Генерация текста только после фильтра наблюдений, а не произвольные «страшные» скрипты. Развивать холод, болевые ощущения, навыки, звук, пахнущую среду, усталость через реальные причинные признаки.
- Android: landscape при первом запуске, portrait только в настройках, режим хранить отдельно от WorldState. Тестировать оба viewport и физический Android 10+ перед обещаниями.
- По указанию владельца **все коммиты делаются непосредственно в main**. Перечислять SHA, тесты и известные ограничения; не заявлять success для неоконченного CI.
- Источник подробных правил: docs/10_ZOMBIE_SURVIVAL.md, docs/11_IMMERSION.md, docs/12_ENDLESS_WORLD.md, а также docs/08_ACCEPTANCE.md Z01–Z20.

## Новый контракт Perception 2.0

`Acoustics` хранит и проверяет детерминированную очередь физически излучённых `SoundEvent`. Перемещение заражённых и их целеуказание строятся по слышимым событиям; только физический контакт может зависеть от фактического соседства с игроком. Нельзя возвращать примитивный `noise_db → player_location` или записывать `infected_approach`/имена прибывших людей в публичный журнал без проверки восприятия. Новые звуковые классы обязаны проходить через `Acoustics.emit` и тесты `P01–P10`. Текущий акустический граф — допущение, требующее смены на порталы/материалы при появлении геометрии. Подробнее `docs/14_PERCEPTION_ACOUSTICS.md` и `docs/adr/0003-acoustic-observation.md`.

## Новые ограничения Anatomy 2.0

`Anatomy` владеет анатомическими областями, повреждением тканей, локальным воспалением и повязками; `Physiology` владеет кровью/водой/теплом/энергией/сознанием и является единственным владельцем их общего баланса. `Kernel` **обязан** проверять `action_limit` и фиксировать `ability_factor`/длительность при старте каждого действия; новые механики не могут обходить ограничение руки/ноги без отдельного физического метода/инструмента. Любое медицинское действие меняет только конкретную рану и учитывает реальные материалы, время и давление. Обязательно проверять любые новые dictionary keys как обычные String для строгого JSON save. Старые сохранения с одиночной раной должны мигрировать безопасно. Адреналин не регенерирует ткани и не даёт разрешения на невозможное действие. Это не клинически калиброванная модель. См. `docs/15_BODY_PHYSIOLOGY.md` и `docs/adr/0004-regional-physiology.md`.

## Infected 2.0: инварианты для агентов разработки

Заражённые **персистентны**, у них нет спавна по триггеру UI, таймеру или повторному входу в зону. Нельзя возвращать `noise_db→player_location` как телепатическое целеуказание. У каждого есть `last_stimulus_sequence`, memory/search, RNG, поза и региональная `Anatomy`. Столкновения с дверями происходят на настоящем ребре карты, накопленное `damage_j` не восстанавливается по скрипту, подпорка тратит материал. Обязательно фильтровать скрытые наблюдения через `Perception`; падение, захват и борьба обязаны менять локальные ткани/кровь, время/ресурсы. Мигрировать save v1/v2→v3 без изменения seeded ID и без новых существ; проверять `test_infected_navigation`, `test_infected_behavior`, `test_infected_gameplay`, `test_infected_anatomy` и полный CI. Существующий граф из семи мест — **не** NavMesh, геометрические детали не заявлять реализованными. См. [главу 16](docs/16_INFECTED_BEHAVIOR.md) и `docs/adr/0005-infected-physics.md`.
