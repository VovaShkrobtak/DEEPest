# DEEPest — 13. UI/UX Overhaul 2.0: интерфейс субъективного выживания

Статус: нормативная спецификация с реализованным первым UI-проходом. Не считать все целевые системы выполненными без теста и конкретного коммита.

## 1. Основной инвариант
Игрок видит не фактическую базу данных мира, а то, что персонаж сейчас наблюдает, вспоминает или измеряет. Истинное состояние мира не находится в дереве визуальных контролов. Поток:

```text
SimulationKernel → Observer.build(...) → публичный ObservationSnapshot
                                          ↓
                         Presentation.build(snapshot, actions)
                                          ↓
                  GameUI (раскладка/текст/кнопки/навигация)
                                          ↓
                     Kernel.command / cancel / step
```

`src/application/presentation.gd` — чистый трансформатор без OS, SceneTree, сохранений и генерации случайных чисел. Он не изменяет входящий снимок, не читает `Kernel._state`, не рассчитывает опасность по скрытым координатам врагов. `GameUI` не вносит физических изменений в мир иначе чем вызовом публичной команды.

Текущий `Observer` пока использует упрощённые доменные `observe`-методы; зрение/слух без физической модели освещения, преград и повреждений органов чувств — известное ограничение. Честная презентация недостаточна, если исходные наблюдения ошибочно раскрывают сущности; этот долг должен устраняться в наблюдателе.

## 2. Компоновка

Главный экран: верхняя строка названия и времени, компактный читаемый контекст, центральный `ScrollContainer`, статус сообщения/результата, ввод команды, на узком устройстве — нижняя зона быстрой навигации. Вертикальная прокрутка находится только у содержимого, а не скрывает постоянно ввод и основные вкладки.

Широкий экран: боковая колонка разделов, центральное чтение, боковая панель условий/ощущений/принадлежностей. Каждая боковая панель сворачивается независимо. Сворачивание не может изменять `time_s`, `revision`, `journal` или действие.

Узкий экран: нижние вкладки **Мир, Действия, Вещи, Тело**, пункт **Ещё**, дополнительный выбор разделов сверху. Ощущения вынесены в компактную раскрываемую панель. Нижние элементы должны учитывать системную клавиатуру и безопасную область Android. Тач-контролы не меньше 48 dp на реальном экране; требуется проверка размеров физических dp.

При первом Android-запуске — landscape, настройка portrait только по запросу; ориентация не входит в save мира. Логический проектный размер для портрета — 420×900, для компактного landscape — 960×540, для широкого экрана — 1280×720 (фактические размеры подстраиваются под экран). При повороте команда/время/инвентарь неизменны.

## 3. Сенсорная панель и статус

Никаких HP, цифровой степени заражения, процентов жажды/голода/раны в основном UI. Статус состоит из публичных наблюдаемых симптомов и предупреждений: ощущение температуры, повязки/раны, дыхания, сухости во рту, усталости. Дубли одинакового текста удаляются. Если явного дискомфорта нет, формулировка осторожная: «явного дискомфорта нет», а не «организм полностью здоров».

Подсветка важности содержит **текстовую** семантику, не только цвет; высокая контрастность независима от механики. Отключение анимаций не меняет время или вероятность обнаружения. Короткая анимация текстового уведомления доступна при снятии настройки «Сокращённое движение»; по умолчанию анимации отключены.

## 4. Контекстные действия и внимание

Единственный источник исполняемых действий — `Kernel.available_actions()`. Презентация фильтрует недоступные варианты; скрытые отрицательные причины не должны раскрывать состояние неизвестного врага или далёкого объекта. Все кнопки отправляют `Kernel.command(id, parameters)`.

Время на кнопке — только оценочное, не обещание. Моментально кажущиеся действия занимают игровое время в `Kernel` по правилам механики; интерфейс не начисляет расход сам.

`attention=exploration` когда нет наблюдённой угрозы и нет работы; `attention=work` когда персонаж исполняет действие; `attention=alert` только когда предупреждение о воспринимаемой угрозе содержится в публичном снимке. Враг не включает боевой режим лишь потому, что `_state.zombies` фиксирует его за стеной. Первые действия при воспринимаемой угрозе: прислушаться, отступить (если допустимо), переместиться, но не скрытая телепортация. Потеря сознания/смерть ограничивают список по правилам мира.

Критические немедленные действия не требуют модального подтверждения; окончательное удаление прохождения защищено явным подтверждением.

## 5. Пустые состояния, память, журнал

«В поле зрения никого нет» не означает «вокруг никого не существует». Не классифицировать незамеченного NPC как погибшего. Память — записи **прошедших наблюдений**, отделённые от текущей информации. Старые факты могут устареть; невидимый NPC не появляется в кнопках разговора.

Публичный журнал и сохранение имеют собственный контракт; `debug_snapshot` допускается только в явно включаемой панели диагностики разработчика и не используется для главного интерфейса.

## 6. Доступность и производительность

Настройки: шрифт 100/125/150/200%, высокий контраст, сокращённое движение (по умолчанию включено), portrait opt-in. Клавиатура: Ctrl+1…8 для вкладок, Escape закрывает список. Длинные тексты корректно переносятся; мобильные кнопки не перекрывают строку ввода. При изменении вкладки мир не продвигается.

Никаких обязательных звуковых уведомлений. Реализован опциональный короткий и тихий синтезированный звук кнопки (по умолчанию выключен); интерфейсное аудио **не создаёт физических акустических событий симуляции**. Мирный звук «скрип двери» создаётся *действием* через модель среды, не нажатием кнопки GUI.

## 7. Регрессионная приёмка

| ID | Условие | Ожидаемое |
|---|---|---|
| UI01 | Скрытый враг, угроз в snapshot нет | Вкладка опасности/отступление не раскрываются |
| UI02 | Слуховое предупреждение в snapshot | Появляется заметный сигнал/доступные немедленные действия |
| UI03 | Работа активна | Режим работы; чтение другого раздела не сбрасывает действие |
| UI04 | Персонаж мёртв | Нет исполняемых игровых действий, только перезапуск/настройки |
| UI05 | Нет видимых людей | Нейтральная формулировка, нет кнопок взаимодействия с NPC |
| UI06 | Смена вкладки и панелей | `Kernel.export_state()` идентичен до и после |
| UI07 | Включение высокого контраста | Сохраняется в настройках без изменения мира |
| UI08 | Переход 390×844 ↔ 1280×800 | Центр читается, ввод и навигация внутри viewport |
| UI09 | 200% текст | Нет горизонтального выноса, действие доступно |
| UI10 | Android landscape → portrait | Настройка сохранена, нет сброса действия; физический тест обязателен |
| UI11 | Отмена работы с любого раздела | Время/ресурсы не откатываются, autosave сохраняется |
| UI12 | Повторная презентация одного снимка | Входные данные не мутируются, выход одинаков |
| UI13 | Отказ из-за неизвестного скрытого состояния | Не видны приватные причины от kernel |
| UI14 | Невидимый удалённый NPC | Нет имени, местоположения, расписания во вкладках |
| UI15 | Включение/выключение движения и звука UI | Никакого эффекта на SimulationKernel |
| UI16 | Поворот экрана при активной виртуальной клавиатуре | Ввод/курсор доступны, проверено на физическом Android |

Проверенный автоматический срез — `tests/test_presentation.gd`, `tests/test_ui.gd`, `tests/test_ui_attention.gd`, `tests/test_project_viewport.gd`; пункты с устройством, screen reader и многоорганной сенсорикой пока требования. Статус конкретного SHA фиксирует GitHub Actions.
