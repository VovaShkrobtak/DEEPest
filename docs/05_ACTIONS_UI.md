# DEEPest — 05. Действия, взаимодействия, текстовое представление, UX

## 1. Принцип
Интерфейс — наблюдатель и отправитель команд, но никогда не источник физических последствий. Любой объект предоставляет возможности (affordances) на основании доступных компонентов, среды, знаний, инструментов, состояния тела и расстояния. Интерфейс не содержит таблицы «если это печь, то всегда можно развести огонь».

## 2. Структура ActionDefinition
action_id, actor requirements, target capabilities, resource reservations, geometric/access preconditions, tool alternatives, skill/knowledge requirements, duration model, movement/posture, stages, energy/exertion, interrupts, process hooks, outcomes, emitted events, observation policy, recovery hints, rollback semantics.
Команды типизированы: actor, verb, target IDs, quantity with units, tool, destination, optional safety preference. Действие может иметь несколько результатов из физических условий, но результат не определяется только текстом кнопки.

## 3. Жизненный цикл
DISCOVERABLE → SELECTED → VALIDATED → RESERVED → RUNNING(stage n) → COMPLETED / INTERRUPTED / FAILED / BLOCKED; возвращаемые ресурсы, израсходованные части и оставшиеся объекты учитываются раздельно.
Перед стартом: доступность руки/инструмента, поза, расстояние, видимость, вместимость, температура, знания, время, конкурирующие действия других агентов.
Во время действия: усталость, расход энергии и материалов, шум, теплообмен, прогресс; NPC и мир продолжают действовать. Если предмет переместили, дверь открылась, начался пожар или персонаж потерял сознание, пересчитать допустимость стадии.
После прерывания: реалистичный остаток, например недосушенная ткань, распиленное наполовину бревно, частично заполненная канистра, разобранный механизм; нельзя вернуть мир к прошлому при уже затраченном ресурсе.

## 4. Каталог глаголов (все data-driven)
Воспринимать: осмотреть, прислушаться, принюхаться, ощупать, измерить прибором, проверить состояние, сравнить, вспомнить, расспросить.
Двигаться: пройти, красться, бежать, ползти, подняться, спуститься, укрыться, сесть, лечь, перепрыгнуть/перелезть (через проверку геометрии).
Манипулировать: взять, положить, переместить, поднять, держать, закрепить, открыть, закрыть, завернуть, отсоединить, привязать, разрезать, сломать, разобрать, почистить, обработать, заточить, проверить.
Пища/вода: набрать, перелить, смешать, процедить, отстоять, нагреть, довести до кипения, остудить, заморозить, приготовить, съесть, выпить, упаковать, хранить.
Огонь/быт: собрать очаг, разжечь, поддерживать, потушить, проветрить, уплотнить окно, согреть, высушить, застирать, помыть, убрать мусор, подготовить постель, поспать.
Организм: обработать рану, перевязать, зафиксировать конечность, принять средство, отдохнуть, выполнять уход, помочь другому.
Строить/ремонтировать: разметить, выкопать, распилить, собрать узел, укрепить, установить, соединить, диагностировать, отремонтировать, испытать.
Социальное: заговорить, предложить обмен, попросить помощь, поделиться, договориться, отказать, передать знание, следовать, звать, предупредить.
Сложные процессы: охота/рыбалка/заготовка/земледелие/наблюдение/ремонт техники/перевозка — композиции базовых команд со стадиями.

## 5. Контекст и доступность
Список возможных действий сортируется по контексту и группам; показывает явную причину недоступности («занята правая рука», «слишком далеко», «нет подходящей тары», «вы не видите крепление») только если персонаж может эту причину знать.
Если игрок пытается недоступное действие, не молчать: выдавать конкретное наблюдаемое объяснение и возможные пути решения. Не раскрывать секреты: вместо «яд в воде» — «вода пахнет растворителем», если это воспринимаемо.

## 6. Свободный ввод
Обязательный deterministic grammar/parser, независимый от LLM. Слои:
нормализация RU/EN, словари морфологических вариантов и синонимов → распознавание намерения → поиск референтов по знаниям/видимости → единицы/количества → typed ActionCommand → проверка ядра → результат.
Примеры: «перелей пол-литра из кружки в бутылку», «заткни щель старой курткой», «сними мокрые носки», «осмотри окно», «позови соседа».
При неоднозначности — выбор из реальных доступных объектов; при неизвестном глаголе — подсказка возможных команд; ошибку не интерпретировать как случайную опасную команду.
Опциональный удалённый или локальный языковой интерпретатор может лишь предлагать типизированные команды; отключён по умолчанию, не обязателен для любой механики, не имеет доступа к скрытому WorldState и не может сам изменять игру.

## 7. Результат как описание, а не таблица статистики
Output pipeline: state deltas/events → perception filters → narrative template → locale/grammar → display message. Возможны несколько точек зрения: тело («ноги ломит от холода»), предмет («крышка плохо закручена»), мир («ветер усилился»), социальное («сосед смотрит настороженно»).
Прозрачность причин: в журнале наблюдаемые события, в debug — реальный причинный граф. Противоречивые сообщения («сухая одежда» и «она мокрая» в одной временной точке) — ошибка контрактов.
Подсказки не раскрывают точную массу бактерий или температуру тела без соответствующего измерения; можно сообщать разумные диапазоны с неопределённостью.

## 8. Мобильный интерфейс
Godot Control без фиксированной пиксельной вёрстки:
- верхняя компактная строка: дата/время/место и доступные сигналы опасности;
- основная прокручиваемая карточка описания окружения;
- быстрые вкладки: Осмотр, Действия, Инвентарь, Тело, Журнал;
- панель контекстных действий + строка текстового ввода и история команд;
- модальные выборы цели/объёма/инструмента, не закрывающие всю значимую информацию;
- лог с фильтрами по важности и источнику, без неконтролируемого роста;
- текстовый осмотр предмета/тела с вложенными деталями и связями.
Портретная ориентация в приоритете, адаптация к landscape и desktop. Минимальный размер касания ориентировочно 44–48 dp; динамический шрифт, системные отступы, экранная клавиатура, отсутствие hover-only механик.
Для Android 10/малой RAM: виртуализация длинного журнала, переиспользование UI элементов, отсутствие загрузки всех описаний в дерево Control.

## 9. Доступность и локализация
Шрифт масштабируется, высокая контрастность, отключаемые анимации, опция сокращённого текста, фильтр повторов, управление клавиатурой/клавишами геймпада, поддержка экранных читалок по техническим возможностям платформы.
Русский — исходный locale; движок текста поддерживает падежи, склонения чисел/единиц, пол/одушевлённость объектов и plurals через шаблонный движок и метаданные. Английский — отдельные словари и шаблоны.
Повествование не должно иметь случайных стилистических конфликтов и повторять одинаковые сообщения 500 раз; narration dedup без потери событий ядра.

## 10. Обучение без навязчивых туториалов
Ненавязчивое объяснение системы через осмотр, заметки, книгу знаний, подсказки по известным процедурам. Не подменять эксперимент квестом с однозначным правильным ответом. Персонаж может узнать о вреде дымящей печи от опыта, свидетеля, записки или прибора, но текст не сообщает скрытые расчёты.
Отдельный учебный старт с подготовленной ситуацией не отличается по правилам симуляции от обычного прохождения.

## 11. Журнал, история, сохранения
Журнал игрока содержит наблюдения, свои действия, слова NPC, гипотезы, заметки, карту известных связей, рецепты/процедуры, следы и запасы по последнему наблюдению. Debug trace скрыт и отделён.
Сохранение можно запросить вне неконсистентной транзакции; интерфейс обязан объяснять, если действие в процессе, и обеспечивать сохранение промежуточного stage state по правилам 06.

## 12. Тесты интерфейса и команд
- Все действия доступны сенсором, ни одно не требует мыши или hover.
- Parser правильно разбирает количества (0,5 л / 500 мл), единицы, синонимы, неполные и неоднозначные фразы.
- Недоступное действие не списывает ресурсы и не создаёт незаметных мутаций.
- Два разных экрана отображают один и тот же snapshot, без рассинхронизации.
- При отключённом AI-парсере полный обязательный набор команд продолжает работать.
- Журнал не показывает невидимые действия NPC как всеведущий рассказчик.
- При прерывании длительного действия прогресс не исчезает без физической причины.
- Крупный шрифт, длинные слова, очень узкий экран и экранная клавиатура не перекрывают кнопки.

## 13. UI ужасa и горизонтальный Android

Никаких экранов «Миссия выполнена», обязательных сюжетных ориентиров, победы утром или конечного сообщения спасения.
Заражённый отображается только если органам чувств персонажа доступны его признаки: шарканье, движение в сумерках, шорох у стены, запах, контакт. Контекстные действия «Прислушаться», «Отступить» и дальнейшие «Тихо открыть», «Подпереть», «Осмотреть щель», «Бросить предмет», «Проверить дверь», «Укрыться», «Задержать дыхание» могут появляться лишь с настоящими prerequisites.
Пороговый смартфон Android 10: по умолчанию горизонтальная ориентация 1280×720 logical; в «Настройках → Ориентация» — вертикальный режим с persistence отдельно от saves. Portrait переключает design viewport, текст и кнопки не становятся микроскопическими; экраны и операции едины для двух режимов.
Точная полная схема, ощущения и acceptance в [11](11_IMMERSION.md).
