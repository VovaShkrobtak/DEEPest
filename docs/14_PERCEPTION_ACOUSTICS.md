# DEEPest — 14. Восприятие 2.0 и физическая акустика

**Реализация:** `src/domain/acoustics.gd`, `src/application/perception.gd`, `src/application/observer.gd`, `src/core/kernel.gd`, `src/domain/zombies.gd`.

**Статус:** действующий, детерминированный, *редуцированный* акустико-сенсорный симулятор, а не полноценная трёхмерная акустика, аура звука или научно калиброванная модель органов чувств. Все коэффициенты ниже — инженерные допущения (**assumption**), не измерения конкретных материалов.

## 1. Цепочка ответственности

```text
Kernel.command(id) → фиксированный шаг ≤10 с
                     ├─ Environment (погода, помещение)
                     ├─ World (движение NPC, реальные действия)
                     ├─ Acoustics.advance + emit (сохраняемые Stimulus)
                     ├─ Zombies.advance → Acoustics.can_hear → target memory
                     └─ Physiology (кровь/усталость/сознание)
                                     ↓
Observer.build → Perception.observe (свет, тело, слух, видимость)
                                     ↓
                    публичный snapshot (нет скрытых IDs)
                                     ↓
                         Presentation → GameUI
```

**Системная инварианта:** `player_location` может участвовать в проверке реального физического *контакта*, но не служит целеуказанием для слуха заражённых. Заражённый выбирает целевую локацию из **наиболее заметного услышанного не-заражённого** акустического события: шагов NPC, радио, печи или действий игрока. Он не узнаёт, кто конкретно издал звук, и не следует координате игрока. Собственное шарканье и шум других заражённых не становятся бесконечным самонаводящимся сигналом. При исчезновении/затухании стимула он сохраняет ограниченную память, а не бесконечно отслеживает игрока. `Observer` не вызывает прежнее геометрическое `zombies.observe()` как всезнающий датчик.

UI слышит только обработанные записи. Событие `infected_approach` остаётся в разработческом trace, но его истинное название/координаты не печатаются в публичном журнале. Приход человека ночью не пишет его имя в журнал автоматически: шаги доступны через акустику, внешность/имя — только при визуальной возможности.

## 2. Физическая модель звука (дБ / м / с)

Каждый `SoundEvent` хранит:

```text
sequence: int, time_s: float, location: LocationID,
kind: enumerated acoustic signature, level_db: float @ 1 m,
owner: emitter identity (private), offset_m: float
```

Звук уровня `L1m` распространяется по кратчайшей длине существующего графа локаций. В упрощении:

```text
d = max(1m, shortest_path_m(source, listener) + source_offset_m + listener_offset_m)
L_receiver = L1m - 20 log10(d/1m) - 0.004 d - Σ(partition_loss_db)
```

Здесь `20 log10(d)` — сферическое геометрическое расхождение **звукового давления**, не линейная скорость затухания. `0.004 d` — эффективное приближение для поглощения воздухом (не универсальная частотно-зависимая таблица). Длина маршрута — **игровой surrogate** реального звукового луча: граф дороги не содержит форму здания, внутренние стенки, щели, отражения, дворы и истинные углы. Не утверждать полевую точность дистанций.

**Преграды (один переход помещения наружу):**
- открытое окно: `4 dB` потерь;
- закрытое: по умолчанию `17 dB`;
- голос, шаги, шарканье, дыхание сквозь закрытую перегородку: `21 dB`;
- низкочастотный удар/металл: `14 dB`;
- утеплённая/заделанная перегородка: `25 dB`.

Когда источник и слушатель находятся в разных помещениях, потери обеих границ складываются. Внутри одного узла перегородка не моделируется: *реальной внутрикомнатной геометрии ещё нет*. Числа будут заменены табличными материалами и частотными полосами после появления порталов/дверей и комнат.

## 3. Маскировка дождём и ветром

```text
ambient_db = 24 + enclosure_factor × (2.6 × wind_m_s + 22 × rain_index)
             + (stove_burning ? 6 : 0)
enclosure_factor = 0.42 inside, 1.0 outside
audibility_threshold = max(body_hearing_threshold - attention_bonus, ambient_db + 3)
heard := L_receiver >= audibility_threshold
```

`rain_index` в диапазоне 0..1. Внимательное прислушивание уменьшает **внутренний** порог различения, но не делает неслышный на фоне ливня звук физически слышимым.

Базовая чувствительность персонажа — условные 23 dB, с ухудшением при значимой кровопотере, гипоксии и усталости. Это пока не отдельные ухо/барабанная перепонка/тиннитус и не калиброванные аудиологические пороги. Заражённые имеют индивидуальные seeded пороги 35–43 dB; из не более 24 недавних стимулов они выбирают наиболее заметный по уровню у слушателя и небольшому штрафу возраста. Реакции детерминированы. Модель не использует скрытый флаг «враг рядом → услышал».

## 4. Источники и происхождение событий

- Действия игрока создают повторяющийся физический стимул по классу: шаги, работа инструментом, удар, голос, плеск, треск радио. Источники заданы в дБ @1m, не RPG «шум +20».
- Завершение некоторых действий даёт отдельный короткий источник (окно, дрова, ремонт, наполненная вода, радио); это не звук нажатия кнопки UI.
- Горящая печь и включённое радио дают звуковой поток, пока работают.
- Движение каждого заражённого создаёт шарканье с собственной текущей удалённостью, без генерации зомби по желанию нарратива.
- Реальное прибытие NPC создаёт шаги; набор воды — плеск. Имя NPC не вшивается в акустический сигнал.
- Без `Acoustics.emit` нет соответствующего звука. Обновление вкладки, кнопка интерфейса и системное аудио не генерируют физических `SoundEvent`.

События упорядочены по `sequence`, живут не более 40 с, очередь ограничена 96 элементами; хранение и воспроизведение полностью детерминированы. Полный архив всех звуков за годы не хранится. При возврате к старому сохранению создаётся пустая очередь с часами на текущем времени, без выдуманных воспоминаний.

## 5. Зрение и субъективные ограничения

Освещённость — нормированное приближение `light∈[0,1]`, определяемое временем суток, дождём, типом помещения, открытым окном, горением печи и фонарём. Заявленная полезная дальность:

```text
visual_range_m = 75m × light × physiology_quality
```

`physiology_quality` снижается при дефиците крови, токсическом состоянии и выраженной усталости. Без сознания оба сенсорных канала отключаются. В полной темноте визуальные описания предметов, имён NPC и заражённых не попадают в публичный snapshot, даже если внутренние объекты расположены рядом. При появлении света наблюдение может измениться **без телепортации** сущностей. В текущей coarse-модели у каждой локации один световой контекст: нет отдельных теней, геометрии лучей, высоты окон и закрытых комнат внутри одной локации.

Заражённый подаётся как «движущаяся фигура», пока нет достоверного распознавания. Слуховые описания не выдают `infected_01`, точное положение/силу тела/количество. Слабые звуки становятся «неразборчивым звуком неизвестного происхождения»; повторяющиеся сообщения группируются. Текст полностью доступен без звукопроигрывателя.

## 6. Save, ошибки, границы

В state добавлено `acoustics={schema_version,time_s,sequence,events}`. При открытии сохранения без этого ключа миграция восстанавливает **пустую** звуковую очередь, привязанную к времени мира. Валидатор отвергает повреждённые ID источников, несуществующие локации, отрицательные/NaN/запредельные величины, будущее время, дубли номеров, чрезмерные очереди; невалидный save не меняет живой мир. Значения `int`/целочисленный `float` корректны после JSON roundtrip.

Механика до сих пор не имеет: реального акустического трассирования, препятствий **внутри** локации, частотных спектров/отражений/реверберации/доплера, раздельных настоящих ушей и слуховых травм, направленного слуха по азимуту, обоняния с ветровым переносом, полного распознавания голосов/NPC и общего слуха у мирных NPC. Нет акустических полевых измерений и не выполнялась проверка на физическом Android. Это явно обозначенные границы **первой реализации Perception 2.0**, а не замаскированные как готовые функции.

## 7. Автоматические проверки

`test_acoustics.gd`: геометрическое затухание; длина графа; окна/утепление; дождь/ветер; пороги; скрытые источники; TTL; неверные значения; JSON/legacy save.

`test_zombie_acoustics.gd`: нет всеведения без стимула; закрытое/открытое окно; дождевой шум меняет обнаружение.

`test_perception.gd`: непроглядная ночь; включение фонаря; кровопотеря ухудшает видимость; бессознательное состояние; без утечки ID.

`test_acoustic_integration.gd`: NPC приходит ночью, шаги слышны, личность не выдаётся; сохранение звуковых событий; прислушивание не подавляет ливень магически.

`test_zombies.gd`, `test_ui_attention.gd`, `test_transactions.gd`, `test_validation.gd`, `test_soak.gd`: боевой контакт, наблюдения в процессе работы, физические последствия, проверка миграции и детерминированный запуск.

Критерий принятия: каждый новый коммит должен пройти импорт Godot 4.6.3 и весь `python3 tools/run_tests.py` в GitHub Actions; `docs/VALIDATION.md` фиксирует точный SHA/ссылку на run. Результат CI не равен калибровке или тесту Android.
